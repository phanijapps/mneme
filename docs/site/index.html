mneme

AI Agent Memory & Recall System

A high-performance Go service for storing, retrieving, and sharing AI agent memories with 4-way hybrid search, built on PostgreSQL + pgvector.

🐹 Go 1.26 🐘 PostgreSQL 16+ 🔢 pgvector 0.8+ 📜 MIT License

🔵 Conceptual Layer

What the system models: memory types, relationships, agents, sessions

  • Memory types (episodic, semantic, procedural, working)
  • Entity relationships and temporal validity
  • Agent sessions and context windows

🟣 Logical Layer

Component contracts, interfaces, and data flows

  • Memory Encoder interface
  • Retrieval Engine with 4-way fusion
  • Recall Router and Lifecycle Manager

🟢 Physical Layer

PostgreSQL + pgvector storage, deployment bindings

  • pgvector HNSW indexes for ANN
  • Full-text search via tsvector
  • Recursive CTEs for graph traversal

7 Core Components

📝 Memory Encoder

Converts raw content into structured memories with embeddings. Handles multiple content formats (markdown, plain, JSON) and computes embeddings using configured models.

🗄️ Memory Store

System of record for memories. Implements supersession-first retention — memories are never hard-deleted, validity intervals close and replacements link via supersedes chain.

🔍 Index Manager

Maintains vector (HNSW), full-text (GIN/tsvector), and graph (recursive CTE) indexes. Coordinates index refresh and handles embedding model registry.

⚡ Retrieval Engine

Executes 4-way hybrid retrieval: vector similarity, lexical BM25-like rank, graph traversal via CTEs, and temporal weighting. Fuses results with Reciprocal Rank Fusion.

🔀 Recall Router

Routes recall requests to appropriate retrieval strategies based on query type, memory type filters, and context requirements. Orchestrates the retrieval pipeline.

🔄 Memory Lifecycle Manager

Handles memory promotion (episodic → semantic), decay scoring, TTL expiry, and shared space synchronization. Implements the supersession workflow.

👥 Shared Memory Sync

Manages SharedMemorySpace for cross-session, cross-user, and cross-agent memory sharing. Handles participant access control and artifact synchronization.

4-Way Hybrid Retrieval

Retrieval combines four complementary search strategies and fuses results using Reciprocal Rank Fusion for optimal recall.

1
🔢 Vector Search

pgvector HNSW index for dense semantic similarity with configurable distance metric

2
📝 Full-Text Search

PostgreSQL tsvector + ts_rank_cd for BM25-like lexical matching

3
🔗 Graph Traversal

Recursive CTEs over memory_links for relationship-aware retrieval

4
⏰ Temporal Weighting

Time-decay scoring with validity range filtering

⟡ Reciprocal Rank Fusion

Combined scores ranked across all four strategies

RecallRequest Options

type RecallRequest { query: string // text to match memory_types: ["episodic", "semantic", ...] // type filter space_ids: [UUID] // shared spaces to search owner_filter: {type, id} // access control time_range: {from, to} // validity filter entity_filter: [entity_ids] // entity affinity top_k: 50 // default: 50, max: 200 rerank: bool // enable cross-encoder rerank include_archived: bool // include archived memories }

Memory Taxonomy

Based on the CoALA framework (Zhang et al., Princeton, 2023) with extensions from production systems like Letta, Mem0, and Zep.

💭

Working Memory

Active information held in-context during a session; bounded by context window size

📸

Episodic Memory

Instance-specific, context-preserved records of past events or interactions

📚

Semantic Memory

Abstracted, generalized facts and knowledge stripped of specific context

⚙️

Procedural Memory

Skills, code patterns, and learned behaviors (how to use a tool)

🔮

Prospective Memory

Planning and future-oriented recall (proposed extension)

📦

Compressed Memory

Summarization/compaction of dense interactions (proposed extension)

Getting Started

📋 Prerequisites

# Install Go 1.26+ # Install PostgreSQL 16+ with pgvector 0.8+ # Docker (for integration tests)

🔨 Build

git clone https://github.com/phanijapps/mneme.git cd mneme go build ./cmd/mneme-api # → mneme-api binary go build ./cmd/mneme-mcp # → mneme-mcp binary

🚀 Run

# Set database URL export DATABASE_URL="postgres://user:pass@localhost:5432/mneme?sslmode=disable" # Run migrations go run ./cmd/migrate up # Start REST API ./mneme-api # Start MCP server ./mneme-mcp

🧪 Test

go test ./... # Unit tests go test ./tests/... # Integration + E2E (requires Docker)
